# 盘古·天机 v0.9 架构与状态边界

## 当前主流程

当前网页维护一条写入链和一条只读复盘链：

```text
全市场模拟：全市场数据 → Top 10 → Top 3次日计划/人工确认 → 跨日 MockBroker
                                                          ↓
持仓复盘：模拟账户实际持仓/订单/成交/费用/净值 → 纪律审计 → DeepSeek只读解释
```

全市场模拟独占账户写入流程；持仓复盘只读同一个 `paper_account.db`，不产生订单。固定 ETF 白名单、历史 ETF 信号和回测快照均不进入复盘。Kill Switch 约束新的模拟开仓，DeepSeek 始终是完全只读的解释层。

## 界面工作区

网页按用户任务而不是版本号堆叠内容：

```text
今日总览 ──→ 全市场模拟（v0.9）
    │         收盘研究 / 次日执行 / 盘中监控
    ├──────→ 持仓复盘
    │         实际模拟持仓 / 净值 / 成交 / 纪律证据
    └──────→ 天机助手
              DeepSeek配置 / Top10与持仓复盘解读
```

默认进入“今日总览”，高频安全状态与下一步入口位于首屏；详细表格和图表只在对应工作区出现。路由是浏览器内的显示状态，不是新的后端工作流状态，不持久化业务数据，也不改变幂等键。页面顶部只有一个共享 Kill Switch，避免不同版本入口产生相互矛盾的安全含义。

“全市场模拟”内另有一条显式人工操作路径：从 Top 10 点击“查看行情”或输入完整沪深主板代码，网页每 5 秒读取一次单标的快照；用户确认后，后端重新获取同一股票及已有持仓行情，再进入模拟账户风控。浏览器看到的价格只用于展示，不直接作为成交价。

## 工作流所有权

```text
15:10 DailyStockResearch
  同花顺只读接口 → 沪深主板过滤 → 40只技术计算 → 20只财务校验 → Top10/Top3计划
                                    ↓
09:35 DailyResearchService → 计划/交易日/时效校验 → PaperPortfolio 卖出优先 → 本地模拟买入
                                    ↓
09:35–14:55 每5分钟 → 新快照 → 8%止损 → T+1立即卖出或次日待退出
```

`DailyStockResearch` 只生成确定性研究证据；`DailyResearchService` 拥有流程时序和失败关闭；`PaperPortfolio` 独占模拟现金、持仓、订单、成交、T+1、净值和幂等语义；`WorkbenchService` 只从 `PaperPortfolio.review()` 生成复盘合同。网页只调用生成客户端。

```text
网页选择股票 → GET /market/quote → 同花顺单标的快照（每5秒轮询）
      ↓ 用户确认
POST /paper/orders/buy → 服务端重新报价 → 风控 → PaperPortfolio → 本地订单/成交/持仓
                                                   ↓
GET /workbench → PaperPortfolio.review → 实际持仓/净值/执行证据（不读取白名单）
```

## 数据边界

核心接口：代码表、全市场行情快照、股票前复权历史日线、财务指标和交易日历。任一核心能力缺失都会关闭自动模拟执行。热榜接口是非核心上下文，失败只产生警告。

行情接口是轮询快照，不宣称逐笔实时。快照超过配置时效、分页不完整或缺少计划标的时禁止模拟成交。手动买入还要求官方交易日且处于 09:30–11:30 或 13:00–15:00；休市时可以查看最后快照，但不能提交模拟买单。

## 状态语义

- 研究计划：`output/research/history/YYYY-MM-DD.json` 不可变日档；`latest.json` 指向最近成功计划。
- 采集状态：`output/research/status.json` 独立记录成功或失败，避免旧成功计划掩盖当日失败。
- 模拟账户：`output/paper_account.db` 跨进程保存账户、持仓、订单、成交、净值与监控事件。
- `paper_automation_enabled`、`live_trading_enabled`、`can_submit_orders` 是三个独立状态，不互相推导。
- 计划仅对下一个官方交易日的 09:35–09:45 有效；过期计划不补发。
- 订单业务键为“交易日 + 计划日 + 股票 + 方向”；同键重复请求返回原订单，不新增成交。
- 手动模拟买入使用调用方 UUID 形成独立业务幂等键；网络重试返回原订单，不新增成交。
- 持仓复盘没有独立持仓集合；它始终读取同一模拟账户，空仓时返回空列表而不是配置白名单。
- 最近 `paper_nav` 提供复盘估值；没有净值快照时按平均成本保守估值并明确标记来源。

## 风控顺序

1. 校验研究完整性、官方交易日、计划有效期和执行窗口；
2. 校验行情时间、计划标的报价与涨跌停风险；
3. T+1 滚动可卖数量；
4. 优先卖出待止损和跌出 Top 3 的可卖持仓；
5. 检查 Kill Switch 与 10% 组合回撤；
6. 按 100 股整数手、20% 单股目标和 60% 总仓位买入；
7. 保存订单、成交、费用、持仓与每日净值。

手动模拟买入复用第 2、3、5、6、7 步，并额外限制最多 3 个持仓、单股市值不超过权益 20%、总市值不超过权益 60%。页面按钮状态只作预提示，服务端检查才是最终决定。

同日新买股票跌破止损线时只登记 `pending_exit`，次日优先卖出且当日不重新买回该股票。

## 模型边界

模型服务与研究评分、风控、模拟账户完全分离。模型只有经过净化的只读证据，不能访问同花顺 Key、模拟数据库连接、订单方法或实盘开关。模型不可用时确定性工作流照常运行。

DeepSeek配置由本机网页提交到固定提供商接口。服务端先验证 `/models`，成功后才保存到当前Windows用户环境并热重载；Key不进入项目文件、网页状态、日志或OpenAPI。DeepSeek V4仅使用非思考JSON响应解释当前Top 10或模拟持仓复盘，输出始终带有 `used_for_execution=false`。

## 明确不存在的能力

- 无 SuperMind、QMT、PTrade 或普通同花顺客户端控制；
- 无证券账户认证、实盘报单或撤单；
- 无新闻抓取和基于自然语言的自由选股；
- 无自动修改策略、权重或风控参数。
